# 叶游泳小程序 v1.1 产品优化说明

目标：从“能用”升级到“好用”，围绕老板、教练、学员三类角色，强化约课、排课、出勤、课消、续费闭环。

## 同类产品对标结论

市面上健身/游泳/少儿培训约课系统的核心竞争力通常不在复杂商城，而在：

1. 预约规则清晰：名额、候补、取消时限、审批状态明确。
2. 教练现场效率：今天课表、点名/确认出勤、课后记录快速完成。
3. 老板经营看板：待办、低课时、续费、今日上课、异常提醒。
4. 学员家长体验：下一节课清楚、剩余课时清楚、推荐可约时间清楚。
5. 课消和续课闭环：确认出勤后扣课，低课时触发续课跟进。

## 本次已落地优化

### 老板角色

- 首页新增“今日待办”：预约审批、续课申请、低课时风险。
- 首页新增“低课时/欠课提醒”，老板可直接进入学员筛选跟进续费。
- 学员页新增筛选：全部、低课时、欠课、已完成、月卡。
- 排课页去掉硬编码默认学员/教练，改为选择学员后自动带出校区和教练。
- 预约审批新增确认/拒绝/取消原因输入，减少误操作。

### 教练角色

- 首页新增“今天课程”，优先服务现场上课场景。
- “待确认”只统计今天及以前未确认课程，避免把未来课程误当催办。
- 课程卡展示学员剩余课时和状态，确认出勤前有课时影响提示。
- 首页新增“我的空余提交”，展示待发布/已发布/已满状态。

### 学员角色

- 首页新增“下一节课”卡片，家长一眼看到下次上课时间。
- 预约页推荐从 1 个升级为 3 个推荐时间。
- 可约时间展示已约/总名额/剩余名额。
- 我的预约增加状态解释：待审批、已生成正式课程、被拒后可重选等。
- 课程申请支持选择课程产品，不再默认第一个课程。

### 数据与规则层

- `mock-store` 给空余时间统一计算：`pendingCount`、`approvedCount`、`bookedCount`、`left`、`fillRate`、`statusLabel`。
- `rules.js` 增加统一日期工具：`toDate`、`daysFromToday`、`dayLabel`、`sortByDateTime`。
- 流程测试补充容量、重复预约、课程产品申请、可约名额等场景。

## 下一阶段建议

1. 增加课后反馈/成长记录：教练课后给学员打标签和备注，学员端可查看成长记录。
2. 增加请假/补课券：家长可申请请假，老板审批后生成补课额度。
3. 增加订阅消息：预约通过、被拒、上课提醒、低课时提醒。
4. 增加老板经营趋势：近 7 天上课数、课消数、续费申请、教练课时排行。
5. 接入真实 CloudBase 后补分页、索引和数据迁移脚本。
