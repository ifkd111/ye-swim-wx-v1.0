# 版本记录

## v1.4.2

- 教练和学员统一使用老板登记的手机号登录，系统按账号绑定自动进入对应角色首页。
- 登录入口明确要求先输入登记手机号，再调用微信手机号验证，输入号码与微信验证号码不一致时拒绝登录。
- 未登记、已停用、重复绑定或已绑定其他微信的手机号继续阻止登录，并给出对应提示。
- 老板新增教练和学员时手机号均为必填；保存后账号显示“待首次登录”，首次验证后显示“微信已绑定”。
- 老板可解除旧微信绑定，教练或学员随后可用登记手机号在新微信上重新验证。

## v1.4.1

- 老板首页增加明确的教练人数和教练管理入口，不再把人员管理藏在模糊的“管理”按钮里。
- 新增独立教练列表，集中展示手机号、校区、关联学员、微信绑定和启停状态。
- 新增教练时自动生成 `jl` 登录账号，老板只需填写姓名、手机号并点击校区。
- 教练资料支持直接编辑、停用、重新启用和解除旧微信绑定，历史课程不会因停用而删除。
- 学员页改为顶部经营统计、搜索筛选和紧凑学员卡片，新增/编辑表单不再长期占据列表首屏。
- 学员卡片突出剩余课时、消课进度、地点、教练、课程状态和登录状态。
- 学员新增/编辑改用地点、教练和课程点击板块；填写手机号时自动创建或同步学员登录账号。
- 项目 CI 继续使用 `CI机器人1`，代码上传白名单已补当前公网 IP。

## v1.4.0

- 产品结构从“功能菜单”改为三角色任务首页：老板看今日供需，教练看日程和空闲，学员直接看课程日历。
- 学员采用挂号式路径：选择日期、地点、课程、教练空闲时间，确认后生成课程草稿。
- 学员常用校区和当前课程自动预选，课程日历直接标记已排课、待发布和可选择日期。
- 学员可申请当天尚未开始的开放时间，过去时段会自动隐藏并由后端再次校验。
- 学员提交不再绕过老板生成正式排课；名额会先占用，老板发布后才创建课程与核销码。
- 老板首页显示“教练有空 → 学员想上课 → 课程草稿”，支持单节发布和全部发布。
- 老板可在发布前点击草稿换到其他有名额的教练时间，也可以拒绝本次安排。
- 教练首页合并当天课程和空闲提交，点亮多个时间后一次提交，无需进入复杂表单。
- 每周模板的星期、时间、校区和教练选择全部改为点击板块，移除核心流程中的下拉框。
- 全局视觉改为低饱和绿、暖灰底和大块任务卡，弱化后台感、数字看板和无关信息。

## v1.3.0

- 三角色深度体验后重排高频入口：学员先看下一节课和预约，教练先处理到课，老板先发布和看当天运营。
- 每周排课模板改为云端保存，老板换设备或清缓存后仍可继续使用。
- 修复未绑定 `openid` 账号可被伪造会话使用的鉴权缺口；教练和学员禁止账号密码绕过手机号验证。
- 修复教练首页可能读取全部学员续课申请的角色数据越界，教练只接收自己授课所需的数据。
- 老板默认密码不再被登录流程自动恢复，老板换绑和空库初始化改为默认关闭的显式环境开关。
- 清库和种子导入接口增加默认关闭的总开关，旧密钥即使泄露也不能直接改写线上数据。
- 账号页支持老板解除教练/学员旧微信绑定；修改手机号会自动使旧微信会话失效。
- 教练不能提前核销未来课程，已请假/已取消课程不再混入待确认；续课申请和预约提交增加防重复操作。
- 老板端新增每周固定排课模板，可生成下周预览后一键发布，并支持复制本周、临时加课和停止继续预约。
- 批量发布自动跳过同一教练同一时间的重复课程，老板可查看每个时间的真实已约人数。
- 学员首页下一节课可直接出示核销码或申请请假，减少进入记录页后再次查找课程的操作。
- 教练首页新增扫码核销，直接确认出勤后可立即填写课后反馈。
- 老板首页展示有数量的待处理事项，“今日上课”会直接打开今天的课程筛选。
- 正式环境关闭开发测试角色入口，云端测试登录改为仅在显式配置环境变量后启用。
- 主流程重新收敛为“老板发布课表、学员直接选课、教练确认上课、老板看账”，弱化审批和复杂后台感。
- 登录页拆成“手机号验证登录”和“老板登录”，教练/学员由老板绑定手机号后用微信手机号能力登录。
- 老板账号页新增手机号管理，保存时校验手机号格式和唯一性。
- 老板首页新增 7/30 天经营看板，展示完成课程、消课数、续课、请假和教练排行。
- 教练/管理员核销后可填写课后反馈，学员端可查看成长记录。
- 学员可提交请假申请，老板审批通过后生成补课额度，并可安排补课排课。
- 新增订阅消息配置占位、数据治理文档和 v1.3 旧账号字段迁移脚本。

## v1.2.0

- 教练和管理员可扫码核销课程，核销会复用原确认出勤扣课逻辑，并防止重复核销。
- 学员首页重组为账户、课程权益、下一节课、课程申请等清晰模块。
- 全局 UI 变量和样式口径进一步统一，卡片、按钮、标签、弹窗和空态风格更稳定。
- README 和小白启动说明统一到当前版本，补充当前能力清单和下一版本规划。
